# aorito - ケータリング現場アンケート自動化

ケータリング案件の現場終了後、その日のうちにGoogleフォームでアンケートを収集し、
Google Apps Script(GAS)で自動的に案件管理スプレッドシートへ反映・要対応案件のメール通知までを行う仕組みです。

## 構成

```
docs/form-questions.md   Googleフォームに設定する質問項目の設計書
gas/Config.gs             案件管理シートのID・列名などの設定
gas/Code.gs                フォーム送信時に実行される自動処理
gas/WeeklyDigest.gs        毎朝「1週間の予定+やることリスト」をメール送信する処理
gas/appsscript.json        Apps Scriptマニフェスト
.clasp.json.example        claspでpush/pullする場合のテンプレート
```

## セットアップ手順

### 1. Googleフォームを作成する

`docs/form-questions.md` の内容通りに質問を作成してください。質問タイトルの文言は
`gas/Config.gs` の `FORM_COLUMNS` と対応させています。文言を変える場合は両方直してください。

### 2. フォームの回答先スプレッドシートを作る

フォームの「回答」タブ → スプレッドシートアイコンから、新しいスプレッドシートを作成して紐付けます。

### 3. Apps Scriptを配置する

紐付けたスプレッドシートを開き、`拡張機能 > Apps Script` でエディタを開き、
`gas/Code.gs`・`gas/Config.gs`・`gas/appsscript.json` の内容をそれぞれ貼り付けます。

claspを使う場合:

```bash
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json  # scriptIdを実際のプロジェクトIDに書き換える
clasp push
```

### 4. Config.gs を実環境に合わせて設定する

- `PROJECT_SHEET.SPREADSHEET_ID`: 案件管理スプレッドシートのID(URLの `/d/` と `/edit` の間)
- `PROJECT_SHEET.SHEET_NAME`: 案件一覧が入っているシート名
- `PROJECT_SHEET.COLUMNS`: 案件管理シート側の実際のヘッダー名に合わせる。
  `SURVEY_STATUS`・`SURVEY_SUMMARY`・`SURVEY_URGENT` に対応する列が案件管理シートになければ、
  事前にヘッダー行に列を追加しておいてください(列がない場合、その項目は書き込まれずスキップされます)。
- `NOTIFY_EMAILS`: クレーム・要対応の回答があったときの通知先メールアドレス

### 5. トリガーを設定する

Apps Scriptエディタ左メニューの「トリガー」→「トリガーを追加」で、以下を設定します。

- 実行する関数: `onFormSubmit`
- イベントのソース: `スプレッドシートから`
- イベントの種類: `フォーム送信時`

### 6. テスト送信して確認する

フォームからテスト回答を送信し、以下を確認してください。

- 案件管理シートの該当案件行に「アンケート回収」「現場振り返りメモ」が反映されること
- 案件名が一致しない場合、フォーム回答スプレッドシート内に「未突合ログ」シートが作成され記録されること
- 「クレーム・要対応事項の有無」で「あり(要対応)」を選ぶと、`NOTIFY_EMAILS` 宛にメールが届くこと

## 動作の仕組み

1. フォーム送信時、GASの `onFormSubmit(e)` が `e.namedValues`(質問タイトルをキーにした回答値)を受け取る
2. `Config.gs` の `FORM_COLUMNS` でキーに変換し、案件管理シートを「案件名」列で検索
3. 一致した行に自動で回収ステータス・振り返り要約・要対応フラグを書き込む
4. 「クレーム・要対応事項の有無」が「あり(要対応)」の場合のみメール通知(平常時の回答で毎回通知が来ないようにするため)
5. 案件名が一致しない場合はエラーにせず、フォーム回答スプレッドシート内の「未突合ログ」シートに記録して後から手動確認できるようにする

## 既知の前提・要確認事項

- 案件管理スプレッドシートの実際の列構成が未確認のため、`Config.gs` の列名はこちらの想定です。
  実シートのヘッダー名に合わせて調整してください(確信度: 中)。
- 通知チャネルはメール(`MailApp`)をデフォルトにしています。Slack等への変更が必要な場合は
  `gas/Code.gs` の `notifyUrgent_` / `notifyError_` を Incoming Webhook 呼び出しに置き換えてください。

## 毎日の1週間予定メール(WeeklyDigest.gs)

毎朝、今日から7日分の予定とGoogle ToDoリストを1通のメールにまとめて送ります。

### 載る内容(上から順)

1. 期限切れのやること(Google ToDoリスト+自動で作るやること)
2. 前回からの変更(前回送信時と比べた新規・変更・キャンセル・削除)
3. 公休日に予定が入っています(個人カレンダーの「公休」などの日に、時間指定の予定がある場合)
4. 重複の疑い(同じ会社名の案件が別の日にもある場合。連日の案件なら問題なし)
5. 未確定の案件・要確認(件名に「未確定」を含む案件)
6. 日別の件数(確定 / 未確定 / ToDo / 人員)
7. 日別の予定(「吉田 裕紀」「Mr.BUFFET関西」の予定と、その日が期限のToDo)
8. 期限なしのやること(最終更新から7日以上たったものは「停滞」と表示)

- Mr.BUFFET関西は大阪案件(カレンダー既定色の茶色)だけを載せます。色を個別に変えた予定と、
  件名に【福岡】【愛媛】がある予定は除外します。
- 未確定案件の件名・説明に「10/5午前中人数確定予定」のような期日があれば、その日の
  やることとして「[自動]」付きで載せます。期日を過ぎても未確定のままなら「期限切れ」に入ります。
- キャンセル案件(件名が「キャンセル」で始まるもの)は非表示にし、件数だけ末尾に出します。
- 確定案件が `DAILY_CAPACITY`(初期値: 1日5件)を超える日は「要人員調整」、未確定を足すと超える日は
  「注意(未確定次第)」と表示します。
- 連日の正しい案件などで「重複の疑い」に毎回出る会社は、`DUPLICATE_IGNORE` に会社名を追加すると表示されなくなります。
- 前回からの変更は、送信のたびにスクリプトプロパティへ保存した予定一覧と比べています。初回は表示されません。

### セットアップ

1. `gas/WeeklyDigest.gs` をApps Scriptプロジェクトに追加し、`Config.gs`・`appsscript.json` も最新に置き換える
   (`appsscript.json` でGoogle ToDoリストを読むための「Tasks API」を有効にしています)
2. `Config.gs` の `DIGEST` で送信先・送信時刻・対象カレンダーを確認する
3. エディタで `sendWeeklyDigest` を1回手動実行し、権限を許可してメールが届くことを確認する
4. エディタで `installDigestTrigger` を1回実行する(毎日 `SEND_HOUR` 時台に自動送信されるようになる)

送信時刻を変えたときは、`SEND_HOUR` を書き換えてから `installDigestTrigger` を再実行してください。
