# 大阪GB 現金出納帳 改修手順と運用ルール

対象: スプレッドシート「大阪GB｜現金出納帳」と、それに紐づく既存のGoogleフォーム

## 目的

「金庫に今いくらあるはずか」を、誰でもいつでも分かる状態にする。

## 改修前の問題

| 問題 | 影響 |
|---|---|
| 処理区分が「入金」「出金」の2つだけ | 売上金・補充・おつりの戻りが同じ残高に混ざり、売上封筒と支払い用のお金を分けて見られない |
| 売上金がフォームにほとんど登録されていない | 金庫全体の金額がどこにも出ない |
| 紙の管理表とフォームの二重記入 | 片方にしかない記録があり、どちらも正しくない |
| 「現金残高」の関数が30行目までしか集計しない | 登録が29件を超えると残高が合わなくなる |
| 開始残高63,409円を実際に数えて照合していない | 残高が正しいか誰も確かめられない |

2026/09/27に金庫を数えた結果: 合計79,968円(釣銭ポーチ50,000円+金庫金29,968円、売上封筒なし)。
フォーム上の残高26,690円より3,278円多かった。この日を基準にして計算し直す。

## 金庫の中身は3つに分ける

| 置き場所 | 金額 | ルール |
|---|---|---|
| 釣銭ポーチ | 1万円×5個=5万円(固定) | 現場のお釣り専用。支払いに使わない |
| 金庫金 | 基準額10万円 | 購入の現金払いに使う。減った分は銀行から引き出して10万円に戻す |
| 売上封筒 | 変動 | 現金売上。支払い・補充に使わず、銀行へ行くときに全部入金する |

## フォームの「処理区分」(5つ)

| 処理区分 | いつ使うか | 残高への影響 |
|---|---|---|
| 出金(支払い) | 金庫金で購入代金などを払った | 金庫金が減る |
| 入金(売上金・茶封筒へ) | ケータリング・オードブルの現金売上を茶封筒に入れて金庫へ | 売上封筒が増える |
| 入金(金庫金の補充) | 銀行から引き出して金庫金に足した | 金庫金が増える |
| 入金(おつり・返金の戻り・その他) | おつりの戻り、返金、空き瓶代など | 金庫金が増える |
| 出金(売上封筒を全部銀行へ入金) | 金庫の売上封筒を全部銀行へ入金した(金額は入金した合計) | 売上封筒が0になる |

- 茶封筒には、受取日・相手先・金額・担当者を書く。
- 紙の管理表への記入はやめる。

## 自動で届くメール

| タイミング | 内容 |
|---|---|
| 支払いの登録で、金庫金が3万円を下回ったとき(下回った1回目だけ) | 補充が必要な額 |
| 金庫金がマイナスになったとき | 登録漏れ・二重登録の確認依頼 |
| 銀行入金の額が、登録済みの売上封筒の合計と合わないとき | 封筒の合計・入金額・差額 |
| 金額が読み取れない、処理区分が5つのどれでもないとき | 登録内容 |
| 毎週月曜9時 | あるはずの金額(ポーチ・金庫金・封筒ごと)、補充が必要な額、14日を超えた封筒 |

## 補充と銀行入金は、社長が大阪GBに出社する日にまとめる

1. 売上封筒を全部入金し、フォームで「出金(売上封筒を全部銀行へ入金)」を登録する
2. 同じ日に「現金残高」シートの「補充が必要な額」を引き出して金庫金を10万円に戻し、「入金(金庫金の補充)」を登録する

## 週1回(月曜):金庫確認

1. 月曜朝のメールの数字を、金庫確認表(`docs/safe-check-sheet.xlsx`)の青い欄に書き写す
2. 2人で、ポーチ・金庫金・売上封筒の順に数える
3. 差額が1円でもあれば原因を書き、当日中に責任者へ報告。登録漏れならフォームで追加登録する
4. 責任者が押印して保管する

## 改修手順(最初に1回だけ、約10分)

1. スプレッドシート「大阪GB｜現金出納帳」を開く
2. `拡張機能 > Apps Script` を開く
3. 左の「ファイル」の+から、次の4ファイルを作って中身を貼り付ける(名前は同じにする)
   - `Config.gs` `Ledger.gs` `Setup.gs` `Code.gs`(`gas-cash/` フォルダ)
   - 最初からある `コード.gs` は、中身が空なら削除してよい
   - すでに別のスクリプトがある場合は、`onOpen` という関数が重複していないか確認する(重複するとメニューが片方しか出ない)
4. 保存し、スプレッドシートを再読み込みする。メニューに「金庫」が出る
5. `金庫 > 初期設定(最初に1回だけ)` を実行する
   - 初回は権限の承認画面が出るので、自分のアカウントで許可する
   - 基準日時: 金庫を数えた日時(例: `2026/09/27 15:00`)
   - 数えた金庫金: `29968`
6. 完了メッセージに「フォームの処理区分の選択肢を5つに変更しました」と出ることを確認する

初期設定で自動的に変わるもの:

- 「現金残高」シート: 3つに分けた計算に作り直す(改修前の内容は「現金残高(改修前)」シートに値で残す)
- 「入出金履歴」の増減額(J列): 新しい処理区分に対応
- 「月別集計」: 処理区分ごとの月別合計に変更
- 「フォーム回答」右側(L〜M列)の残高表示: 新しい現金残高シートを参照
- フォームの「処理区分」の選択肢と説明文
- フォームの「担当者」: 迫田・大岡・吉田・山下・平山・藤川・渡邊・楠・山口・空野・花川 の11名(`Config.gs` の `STAFF_NAMES`)
  - プルダウン/選択式なら選択肢をこの11名にする
  - 記述式なら、この11名の名字以外は入力できないようにする(質問を作り直すと回答シートの列がずれるため、作り直さない)
  - プルダウンにしたいときは、フォームの編集画面で「担当者」の種類を「プルダウン」に変えてから、メニュー `金庫 > 担当者の選択肢を反映` を実行する
  - 担当者が増えたら `STAFF_NAMES` に追加して、同じメニューを実行する
- トリガー: フォーム送信時の通知、毎週月曜9時の週次メール

## 動作確認(改修直後)

1. 「現金残高」の「金庫にあるはずの合計」が 79,968円 になっていること
2. フォームから「出金(支払い)」を1円でテスト登録し、金庫金が1円減ること
3. `金庫 > 週次メールを今すぐ送る` でメールが届くこと
4. テスト登録の行は「フォーム回答」シートから削除する

## 注意

- 基準日時より前の取引は、今後フォームに登録しない(数えた金額に含まれている)。
- 処理区分の文字を書き換えると計算から外れる。選択肢を変えるときは `Config.gs` の `KINDS` も同じにする。
- 金庫を数え直して基準を置き直すときは、「現金残高」のB7(数えた金額)とB14(基準日時)を書き換える。
- 実環境での動作は未確認。計算部分は `node --test tests/ledger.test.js` で確認済み。
