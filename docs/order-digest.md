# デリプロ注文一覧メール(毎朝自動送信)

毎朝7時台に、今日から7日先までのデリプロ案件(確定・保留)を一覧にして `buffet@lit-house.jp` へメール送信します。
50名以上の大型案件は21日先まで先取りして、メール冒頭に「確定締切(開催日の5日前など)」付きでまとめます。

## データの取り方

デリプロにはデータ連携の機能がないため、デリプロが出力してドライブに保存されているPDFを読み取ります。

- 対象フォルダ: `09_見積・受注書類` 配下の案件フォルダ `MMDD_★顧客名`
- フォルダ名の日付で期間内の案件だけに絞り込み、その中のPDFを判定

| フォルダ内のPDF | 判定 |
|---|---|
| 発注請書 / 発注請書(控え) がある | 確定 |
| 見積書しかない | 保留 |
| デリプロのPDFがない | 書類なし(要確認に表示) |

- PDFはGoogleドキュメントに一時変換して文字を取り出し、変換したファイルはすぐ削除します
- 解析結果はスクリプトプロパティにキャッシュし、同じPDFは2回目以降変換しません
- 人数は料理・ドリンクプランの最大数量からの推定です(諸経費・値引・単品・配送などは除外)

## メールの内容

1. サマリー: 確定・保留それぞれの件数 / 人数 / 金額、大型案件数
2. 大型案件: 日付・状態・確定締切(残り日数)・人数・お客様・プラン・金額・場所・社内メモ
3. 日別一覧: 日ごとの案件(保留は黄色、大型は赤で表示)。お客様名からPDFを開けます
4. 要確認: PDFがない、日付不一致、見積書が複数、人数を読めない などの案件
5. 添付: 大型案件のPDF(`ATTACH_MODE` で変更可)

## セットアップ

1. https://script.google.com で新しいプロジェクトを作成(`buffet@` の受信者全員に関係するので、案件フォルダを閲覧できるアカウントで作成)
2. `gas/order-digest/` の `Config.gs`・`Parser.gs`・`Code.gs`・`appsscript.json` を貼り付け
   (`appsscript.json` はエディタの「プロジェクトの設定」→「appsscript.json をエディタで表示する」をONにすると編集できます)
3. 左メニュー「サービス」→「Drive API」(v3)を追加(`appsscript.json` を貼っていれば追加済み)
4. 関数 `testSendToAdmin` を実行 → 権限を承認 → `ADMIN_EMAIL` 宛てに届いた内容を確認
5. 関数 `setupDailyTrigger` を1回だけ実行(毎朝7時台の自動送信が登録されます)

## 設定(Config.gs)

| 項目 | 初期値 | 内容 |
|---|---|---|
| `ROOT_FOLDER_ID` | 09_見積・受注書類 | 探索の起点フォルダ |
| `EXCLUDE_FOLDER_NAMES` | 失注, old | 探索しないフォルダ |
| `DAYS_AHEAD` | 7 | 一覧に載せる日数 |
| `LARGE_LOOKAHEAD_DAYS` | 21 | 大型案件だけ先取りする日数 |
| `LARGE_HEADCOUNT` | 50 | 大型案件の人数基準 |
| `ATTACH_MODE` | large | none / large / all |
| `MAIL_TO` | buffet@lit-house.jp | 送信先 |
| `ADMIN_EMAIL` | yoshida@lit-house.jp | エラー通知・テスト送信先 |

## 前提と注意点

- 案件フォルダ名が `MMDD_` で始まっていないと拾えません(フォルダ命名ルールの徹底が前提)
- 見積書・発注請書をフォルダに保存し忘れると、その案件は一覧に出ません(「書類なし」は出ます)
- 失注した案件は `失注` フォルダへ移すか見積書を削除しないと「保留」のまま表示されます
- 初回はPDF変換が多く時間がかかります。6分制限に近づくと残りは「未解析」として翌日に回します
- テスト: `node tests/order-digest-parser.test.js`(テスト用PDF文字列は架空データ)
