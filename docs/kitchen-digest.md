# デリプロ注文一覧・キッチン指示書メール(毎朝自動送信)

毎朝7時台にGASがデリプロへ自動ログインし、今日から7日先までの注文(確定・保留)を
日別一覧と大型案件(50名以上・21日先まで)一覧に整理して、キッチン指示書(注文別:メイン)PDFを添付して
事業所ごとに送ります。手作業はありません。

| 事業所 | 件名 | 送信先のスクリプトプロパティ |
|---|---|---|
| 大阪 | 【大阪キッチン指示書】 | `MAIL_TO` |
| 東京 | 【東京キッチン指示書】 | `MAIL_TO_TOKYO` |
| 東海 | 【東海キッチン指示書】 | `MAIL_TO_TOKAI` |

送信先が登録されていない事業所は送りません。新しい事業所は `Config.gs` の `OFFICES` に1行足します。

## 仕組み

1. `login.php` にログイン(ID・パスワードはスクリプトプロパティから読む)
2. 集配管理 `deli.php` で、配達日 今日〜21日後・受付=`OFFICES` の各事業所の注文を「確定」「保留」で別々に検索(取消・練習は除外)
3. 検索結果の注文番号で `deli.php?mode=print_kitchen&is_main=true` からキッチン指示書PDFを取得し、OCRを使わずに文字を直接取り出して注文ごとに分解(`PdfText.gs`)
4. 注文番号で保留・確定を付け合わせ、人数を推定してメールを作成
5. 一覧の「全N件」と取得件数が合わない、ログインできないなどの場合は `ADMIN_EMAIL` にエラーメール

## メールの内容

- 件名: `【大阪キッチン指示書】10/11(日)〜10/18(日) 61件(保留2件)・大型10件`
- 合計件数・人数、保留の件数・人数、大型案件の件数・人数
- 確定の催促が必要: 保留のまま3日以内(`PENDING_ALERT_DAYS`)に配達の案件。件名に「要催促N件」と出る
- 保留の色分けと件数から、南海など保留が通常状態のお客様(`NO_PENDING_HIGHLIGHT_CLIENTS`)は除く
- 大型案件(21日先まで): 残り日数・時間・No.・状態・人数・お客様・プラン・お届け先
- 日別一覧: 日ごとの件数・人数と注文明細(保留は黄色、大型は赤)
- 添付: 今日〜7日先のキッチン指示書PDF

## 人数の推定ルール

PDFに人数欄がないため、次の最大値を人数とみなします。

- プラン欄 `【プラン × 数量】` の数量(諸経費・単品・ドリンク単品・LIVE・ケーキは除外)
- 料理明細の数量(複数プランの合計人数分の料理が並ぶため)
- 大皿 `(20人前) 1` は 人前×数量

## セットアップ

1. https://script.google.com で新しいプロジェクトを作成し、`gas/kitchen-digest/` の
   `Config.gs`・`PdfText.gs`・`KitchenParser.gs`・`DeliListParser.gs`・`DeliproClient.gs`・`Code.gs`・`appsscript.json` を貼り付け
2. (Drive API の追加は不要。PDFは直接読み取る)
3. 「プロジェクトの設定」→「スクリプト プロパティ」に次を登録(コードやGitHubには書かない)
   - `DELIPRO_CONTRACT_ID` / `DELIPRO_STAFF_ID` / `DELIPRO_PASSWORD`
   - `MAIL_TO` / `MAIL_TO_TOKYO` / `MAIL_TO_TOKAI`(各事業所の送信先。カンマ区切り。未登録の事業所は送らない)
4. `Config.gs` の `OFFICES` を確認(事業所ID '8'=東京 / '9'=大阪 / '24'=東海)
5. `testKitchenDigestToAdmin` を実行し、権限を承認して `ADMIN_EMAIL` 宛ての内容を確認(送信先が登録された事業所の分が届く)
6. `setupKitchenTrigger` を1回だけ実行

## 注意点

- デリプロの画面の作りが変わると取得に失敗します。その日はエラーメールが届くので、画面の変更点を確認してください
- パスワードを変えたら、スクリプトプロパティの `DELIPRO_PASSWORD` だけを書き換えます
- テスト: `node tests/kitchen-parser.test.js`(テスト用データは架空)
